## Local acceptance checklist
1. From develop clone run node site/core.test.js, node extension/protocol.test.js, node extension/automation.test.js, node extension/catalog.test.js; run node --check for each JS file. Build local extension with node scripts/build-dev-extension.mjs; serve python -m http.server 8000.
2. Install unpacked dist/extension-dev/ in Chrome; disable production extension; open localhost:8000. Verify side panel, dark/light, keyboard and narrow widths. Repeat in Edge.
3. Verify direct Send without extension, Unicode prefill, long prompt fallback, multiple provider links and no automatic URL disclosure when disabled.
4. Grant ChatGPT only, enable Bridge and auto-submit, select ChatGPT and Gemini. Confirm only permitted adapter submits once; denied provider remains blocked. Grant Gemini then test a new request. Use authorized accounts only.
5. For ChatGPT, Claude and Gemini independently send a non-sensitive deterministic prompt (e.g. Translate “Good morning” to Khmer). Inspect actual submitted user text, answer node and stop indicator. Capture redacted screenshot or log; confirm no prior conversation imported. If selectors fail, do not retry automatically.
6. Verify double click, wrong origin, wrong job/token, duplicate sequence, existing composer text, missing login, missing send control, multiple answer nodes, redirect, tab close and browser restart. Confirm no unrelated data extracted.
7. Test manual Send to Main Chat, auto completion only, live partial and terminal status, comparison and JSON export. Verify each response equals actual provider text and source links stay on the provider origin. Check manual selected-text fallback for all other providers.
8. Test side panel draft @mentions, provider detection, permission revoke, app reload and old-job rejection; inspect session cleanup and resource behavior with 3+ tabs.
9. Record exact browser/provider versions, inputs, observed results, screenshots and failures. No release until P1 findings resolved and all mandatory gates pass.
